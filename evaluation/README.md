# Offline RAG Evaluation

The offline runner queries the real policy-bot evaluation endpoint, preserves raw traces,
and scores completed policy responses with both evaluator profiles. It never modifies
Qdrant or ingests files.

## Evaluation flow

The .NET API remains responsible for generating chatbot answers. Python is the offline
test harness and evaluator:

```text
Python evaluation runner
        |
        | POST /api/evaluation/query
        v
.NET API: real RAG pipeline
  - language detection and intent classification
  - TEI query embedding and Qdrant retrieval
  - chatbot LLM answer generation
  - citations, images, form downloads, and trace metadata
        |
        | answer, retrieved chunks, and metadata
        v
Python evaluation runner
  - deterministic product checks
  - RAGAS scoring with separate evaluator LLMs
  - resumable result storage
```

The evaluator LLMs judge the answer generated by the configured chatbot model. They do
not replace the chatbot model or write data to Qdrant.

## Evaluation steps

1. Start Qdrant and TEI.
2. Ingest the audited usable corpus into Qdrant using the existing .NET ingestion API.
3. Start the .NET API with `Evaluation__Enabled=true`.
4. Run `preflight` to verify that every usable audited file is indexed.
5. Run `collect --limit 10` for the required smoke subset.
6. Run `run --limit 10` with the same result directory to calculate RAGAS scores.
7. After reviewing the smoke results, run the full dataset with both evaluator profiles.

## Setup

1. Create `evaluation/config/evaluation.local.json` from
   `evaluation/config/evaluation.example.json`.
2. Set `EVALUATION_OPENWEBUI_API_KEY` for the OpenWebUI profile.
3. Create a Python 3.13 virtual environment and install the scoring dependencies. Python
   3.14 is not supported on Windows because `scikit-network` does not publish a matching
   wheel:

```powershell
py -3.13 -m venv evaluation/.venv
evaluation/.venv/Scripts/python.exe -m pip install -r evaluation/requirements.txt
```

4. Start Qdrant, TEI, and the API with evaluation mode enabled:

```powershell
$env:Evaluation__Enabled="true"
dotnet run --project src/API/PolicyBot.Api.csproj --urls http://localhost:5279
```

## Commands

Run the required corpus preflight:

```powershell
evaluation/.venv/Scripts/python.exe evaluation/scripts/run_ragas_evaluation.py preflight
```

Collect a resumable 10-question smoke subset without evaluator scoring:

```powershell
evaluation/.venv/Scripts/python.exe evaluation/scripts/run_ragas_evaluation.py collect --limit 10 --run-name smoke-10
```

Score the same subset with both evaluator profiles:

```powershell
evaluation/.venv/Scripts/python.exe evaluation/scripts/run_ragas_evaluation.py run --limit 10 --run-directory evaluation/results/smoke-10
```

Re-running a command with the same `--run-directory` resumes completed rows. The runner
fails before querying the chatbot when any usable audited corpus file is missing from
Qdrant. Files marked as parser-error supporting forms by the corpus audit are reported as
excluded until they are replaced or repaired.
